## Как пополняем справочник

1. Ассистент задаёт один вопрос, кандидат отвечает.
2. Разбираем ответ и при необходимости уточняем детали.
3. **Когда разбор закончен**, ассистент добавляет в соответствующий файл вопрос и правильный развёрнутый ответ, включая важные нюансы и примеры, если нужны.
4. Перед новым вопросом ассистент просматривает уже сохранённые темы, чтобы **не задавать дубликаты**. Повторение возможно, если о нём специально попросить.

Формат каждой записи:

```md
## Вопрос: ...

**Ответ:** ...

**Нюансы:** ... (необязательно)
```

Никаких персональных оценок и учёта прогресса. Репозиторий используется как **справочник**, а не дневник собеседования.

> Репозиторий сейчас публичный: опубликованные записи будут доступны другим пользователям GitHub.

## Ориентир: собеседования в российских компаниях

Цель — подготовка на **Senior Go Backend Developer** под практики технических интервью российских продуктовых компаний, банков, маркетплейсов и других работодателей. Не ориентироваться по умолчанию на FAANG/Big Tech и зарубежные interview loops.

Приоритет: язык Go и его особенности (slices/maps/interfaces/nil/defer), runtime/GMP/GC, горутины/каналы/sync/atomic, чтение кода и поиск ошибок; далее — SQL/PostgreSQL, Kafka/Redis, HTTP/gRPC, микросервисы, эксплуатация и прикладной system design. Вопросы должны проверять не только определения, но и понимание подводных камней, поведения программ и инженерных решений. Алгоритмы — по необходимости, не основной фокус. Распределение тем зависит от компании и конкретной вакансии, поэтому это ориентир, а не универсальное правило.

**Не начинать и не продолжать интервью по собственной инициативе**: ждать явной команды пользователя. Новые вопросы — по одному. После завершённого разбора сохранять только вопрос и корректный ответ в соответствующем разделе; без оценок и прогресса. Перед каждым вопросом проверять справочник, чтобы не повторяться.
