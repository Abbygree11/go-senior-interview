# Senior Go Interview

База подготовки к техническим собеседованиям **Senior Go Developer**. Материалы ведутся на русском языке.

## Как проходит интервью

1. Ассистент задаёт **один вопрос** без подсказки и эталонного ответа.
2. Кандидат отвечает как на собеседовании.
3. Ассистент оценивает точность, полноту, нюансы и при необходимости задаёт уточняющие вопросы.
4. **После завершения разбора** ассистент сохраняет вопрос, оценку ответа и выверенный эталонный ответ в `questions/<category>/GO-XXX.md`.
5. Ассистент обновляет [PROGRESS.md](PROGRESS.md), прежде чем переходить к следующему вопросу.

До проверки ответа эталон не публикуется. Уже пройденные вопросы не повторяются случайно; осознанные повторения допустимы для закрепления слабых тем.

## Категории

| Папка | Темы |
| --- | --- |
| `language` | Типы, интерфейсы, generics, ошибки, defer/panic/recover |
| `runtime` | GMP, планировщик, стек, аллокации, escape analysis |
| `concurrency` | Goroutines, channels, select, sync, race conditions, memory model |
| `memory-gc` | GC, heap/stack, профилирование, оптимизация |
| `stdlib` | Context, I/O, time, net/http, инструменты Go |
| `networking` | HTTP, TCP, gRPC, таймауты, устойчивость |
| `databases` | SQL, транзакции, индексы, PostgreSQL |
| `distributed-systems` | Очереди, согласованность, идемпотентность, отказоустойчивость |
| `system-design` | Архитектура, масштабирование, компромиссы |
| `testing-production` | Тестирование, observability, профилирование, CI/CD |

Папки появляются при добавлении первого разобранного вопроса. Единый [шаблон](QUESTION_TEMPLATE.md) и [реестр прогресса](PROGRESS.md) позволяют продолжать собеседование с учётом уже пройденного.

## Оценка

- **Уверенно** — корректный и достаточно глубокий ответ для Senior.
- **Частично** — основа верна, но есть важные пробелы.
- **Повторить** — концептуальные ошибки или недостаточная глубина.

Оценка относится к **конкретному ответу**, а не к уровню кандидата в целом. Если есть неопределённость или детали зависят от версии Go, это явно фиксируется. Сначала проверяются материалы в репозитории, чтобы исключить случайные повторы.

> Внимание: при публичной видимости репозитория записи будут доступны всем.
