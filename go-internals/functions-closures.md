# Функции и замыкания: захват переменных, defer, loop variables, утечки

## 1. Функция — значение

Функции в Go — значения: их можно передавать аргументами, хранить в структурах и возвращать. Функциональные значения не сравниваются друг с другом через `==`, кроме сравнения с `nil`.

```go
var f func(int) int
fmt.Println(f == nil) // true
// f(1)                // panic: call of nil function
f = func(x int) int { return x + 1 }
fmt.Println(f(3))      // 4
```

## 2. Замыкание захватывает переменную, а не обязательно копию числа

```go
x := 1
next := func() int {
    x++
    return x
}
fmt.Println(next(), next(), x) // 2 3 3
```

Замыкание сохраняет доступ к переменной окружения, которая может пережить исходный вызов. Компилятор может разместить её в куче, но физическое расположение определяется escape analysis.

Если хочешь snapshot, передай параметр в новую функцию:

```go
x := 10
f := func(v int) func() int {
    return func() int { return v }
}(x)
x = 20
fmt.Println(f()) // 10
```

## 3. Замыкание + `defer`

```go
x := 10
defer fmt.Println(x)         // аргумент фиксирован как 10
defer func() { fmt.Println(x) }() // читает переменную позже
x = 20
// В конце функции: сначала 20, потом 10
```

Смешиваешь время вычисления аргументов и время исполнения тела — получаешь ошибку на собеседовании.

## 4. Loop variables: Go 1.22 изменил семантику

```go
for i := 0; i < 3; i++ {
    go func() { fmt.Println(i) }()
}
```

В модулях `go 1.22` и новее переменная `i`, объявленная `:=`, существует отдельно для итераций. Но **порядок печати всё равно не определён**, а `main` обязан ждать горутин. В модуле со старой семантикой может проявиться прежний захват одной переменной.

Если переменная объявлена заранее (например, `var i int; for i = 0; ...`), она переиспользуется и конкурентное чтение/запись может вызвать data race. Явная передача `i` аргументом понятна для любого читателя.

## 5. Функция как callback под mutex

```go
mu.Lock()
onUpdate() // может внутри снова Lock той же mu
mu.Unlock()
```

Callback неизвестного кода может заново войти в объект, взять тот же mutex, заблокироваться или надолго зависнуть. Часто лучше собрать immutable snapshot под lock, отпустить mutex, только затем вызвать callback.

## 6. Замыкание удерживает память

```go
func makeCallback(data []byte) func() byte {
    return func() byte { return data[0] }
}
```

Замыкание ссылается на `data`, а тот может удерживать большой backing array до освобождения замыкания. Если нужно только одно значение, захвати `v := data[0]` и замкнись на `v`.

## 7. Value vs pointer receiver и method values

`f := x.Method` — method value: receiver вычисляется при создании method value. Для value receiver это может захватить копию receiver; для pointer receiver — ссылку на объект.

```go
type Item struct{ N int }
func (i Item) Show() int { return i.N }
x := Item{1}
f := x.Show
x.N = 2
fmt.Println(f()) // 1
```

Это особенно важно, когда откладывают метод через `defer`.

## 8. Функция и goroutine: ошибка с `go f()`

Аргументы `f()` вычисляются в текущей горутине, сама функция выполняется новой. Нельзя гарантировать, что goroutine успеет закончить до выхода `main`; нужно явно ждать.
