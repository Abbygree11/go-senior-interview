# Слайсы (`[]T`): что лежит внутри и откуда берутся каверзы

> Цель: по коду предсказывать `len`, `cap`, значения, момент аллокации и то, какие изменения видны через другие слайсы. Здесь речь о слайсах, а не массивах `[N]T`.

## 1. Модель данных

Концептуально слайс — **значение из трёх компонентов**:

```text
slice header
 ├─ data → первый элемент доступной области базового массива
 ├─ len  → число доступных по индексу элементов
 └─ cap  → сколько элементов можно охватить от data до конца доступной ёмкости
                       ↓
       backing array: [A][B][C][D][E]
                          ↑
                    другой слайс может
                    начинаться здесь
```

Это **модель**, а не обещание стабильного Go ABI. Слайс передаётся **по значению**: копируется заголовок, **но не базовый массив**. В отличие от `[N]T`, слайс не сравним через `==` с другим слайсом (допускается сравнение с `nil`).

- `len(s)` — допустимые индексы `0 .. len(s)-1`.
- `cap(s)` — предел обычного расширения слайса через срез. `len(s) <= cap(s)`.
- `nil`-слайс: нулевой указатель, `len=0, cap=0`; читать и делать `append` можно.
- `make([]int, 2, 5)` даёт два элемента со значением 0 и ёмкость не меньше 5 (для `make` задана именно 5).

**Зачем это знать:** разные заголовки могут ссылаться на одни и те же элементы. «Передать слайс как значение» не означает скопировать данные.

## 2. Передача в функцию: видимое и невидимое изменение

```go
func change(s []int) {
    s[0] = 99        // базовый массив — общий
    s = s[:1]        // меняем лишь локальную копию заголовка
    s = append(s, 7) // запись может затронуть общий массив
}
func main() {
    a := []int{1, 2, 3}
    change(a)
    fmt.Println(a, len(a), cap(a))
}
```

Вывод: `[99 7 3] 3 3`. `append` здесь записал `7` поверх второго элемента общего массива, а длина заголовка `a` осталась 3.

**Каверза:** изменения элементов, длины и указателя на backing array — три **разных** действия. Чтобы изменить сам заголовок у вызывающего кода, возвращай новый слайс (`a = change(a)`) или принимай `*[]T`, если на это есть причина.

## 3. Срезы: len и cap считаются от начала среза

```go
a := []int{10, 20, 30, 40, 50}
b := a[1:3]
fmt.Println(b, len(b), cap(b)) // [20 30] 2 4
c := b[:4]
fmt.Println(c)                 // [20 30 40 50]
```

`b` начинается с `a[1]`, поэтому ёмкость 4, хотя длина 2. Обычный срез **не уменьшает cap до len**. Он также не создаёт копию массива.

**Полное выражение среза** `a[low:high:max]` ограничивает ёмкость: `len=high-low`, `cap=max-low`.

```go
a := []int{1, 2, 3}
b := a[:1:1]       // len=1, cap=1
b = append(b, 8)   // вынужден создать новый backing array
fmt.Println(a, b)  // [1 2 3] [1 8]
```

Это способ защитить хвост исходного массива от будущего `append`, но **не** от изменения элементов, уже входящих в `b`: `b[0] = 9` по-прежнему меняет `a[0]` до отделения.

## 4. `append`: почему поведение зависит от ёмкости

`append` возвращает **новое значение слайса**. Если `len+добавленные <= cap`, используется прежний массив; иначе выделяется другой массив, элементы копируются, а дальнейшие записи в него уже независимы.

```go
a := make([]int, 2, 4)
a[0], a[1] = 1, 2
b := append(a, 3)
c := append(a, 4)
fmt.Println(a, b, c) // [1 2] [1 2 4] [1 2 4]
```

Оба `append` пишут в **одно место** `backing[2]`. `b` не владеет отдельной копией. Вызов второго `append` перезаписал значение, которое читает `b`.

```go
a := []int{1, 2} // len=cap=2
b := append(a, 3)
b[0] = 10
fmt.Println(a, b) // [1 2] [10 2 3]
```

Здесь рост потребовал другой массив. **Не угадывай размер будущей ёмкости**: алгоритм роста — деталь runtime, зависит от версии, размера элементов, аллокатора. Код не должен рассчитывать на «cap всегда удваивается».

## 5. `append` с перекрывающимися слайсами

```go
s := []int{1, 2, 3, 4}
s = append(s[:2], s[1:]...)
fmt.Println(s) // [1 2 2 3 4]
```

Операции `append` и `copy` допускают перекрывающиеся области; результат определён семантикой копирования. Но **aliasing остаётся**: несколько слайсов по одному массиву могут неожиданно изменять друг друга.

## 6. `copy`, `slices.Clone` и глубокое копирование

```go
a := []int{1, 2, 3}
b := a        // скопирован header, данные общие
c := append([]int(nil), a...) // новый массив
d := slices.Clone(a)           // новый массив (при len > 0)
a[0] = 9
fmt.Println(b, c, d) // [9 2 3] [1 2 3] [1 2 3]
```

`copy(dst, src)` переносит `min(len(dst),len(src))` элементов. Если `dst` имеет длину 0, `copy` скопирует **ноль**, даже при большом `cap`.

```go
dst := make([]int, 0, 10)
n := copy(dst, []int{1, 2, 3})
fmt.Println(n) // 0
```

Для слайса указателей/карт/вложенных слайсов `Clone` делает **поверхностную** копию: сами вложенные объекты остаются общими. Если нужна изоляция всех уровней — делай deep copy по смыслу данных.

## 7. Удержание памяти маленьким под-слайсом

```go
func header(data []byte) []byte {
    return data[:16] // может удерживать весь огромный backing array
}
```

Пока жив маленький срез, GC считает весь backing array достижимым. Исправление, если нужен независимый маленький результат:

```go
func header(data []byte) []byte {
    return bytes.Clone(data[:16])
}
```

`slices.Clip` ограничивает `cap`, но **не гарантирует нового массива**: не путать `Clip` и `Clone`.

## 8. Удаление элементов и GC

```go
s = append(s[:i], s[i+1:]...)
```

Удалённые ссылочные значения могут продолжить храниться в **хвосте backing array**, даже если они больше не видны через `len(s)`. В зависимости от контекста это может удерживать объекты в памяти. Для слайса указателей обнуляй ненужный хвост (`clear`/`slices.Delete` в актуальном Go) после корректного перемещения элементов. Не обнуляй массив, если другие слайсы всё ещё используют эти позиции.

## 9. `range` и копия элемента

```go
type User struct{ Age int }
users := []User{{10}, {20}}
for _, u := range users {
    u.Age++ // u — копия структуры
}
fmt.Println(users) // [{10} {20}]
for i := range users {
    users[i].Age++ // меняем исходные элементы
}
```

Если элементы — указатели (`[]*User`), копируется указатель, и изменение `u.Age` затронет объект. Учитывай изменение семантики переменной цикла с Go 1.22 (для соответствующих модулей): старые загадки с замыканием переменной `range` не всегда актуальны.

## 10. Concurrency: разные элементы и общий header

Разные горутины могут безопасно писать в **разные элементы** одного заранее выделенного слайса, если никто параллельно не меняет эти элементы/заголовок. Конкурентный `append` в общую переменную без синхронизации — гонка; даже когда хватает `cap`, меняется заголовок, и несколько писателей конфликтуют.

**Практика:** заранее выделить `make([]T, n)` и закрепить уникальные индексы за воркерами; или передавать результаты через канал; или защищать общий слайс mutex.

## Дополнительные каверзы из официальных SliceTricks и `slices` (проверено по Go 1.27)

### 12. `slices.Delete` и ручное удаление — не совсем одно и то же

```go
type Big struct{ Data [1024]byte }
a := []*Big{new(Big), new(Big), new(Big)}
removed := a[1]
a = append(a[:1], a[2:]...)
// len(a) = 2, но элемент хвоста backing array всё ещё может ссылаться на Big.
_ = removed
```

**Почему:** `append`/`copy` перемещают элементы, но **не обнуляют неиспользуемые ячейки за новой длиной**. Отсюда retention: объект остаётся достижимым для GC через массив. Начиная с Go 1.22 `slices.Delete`/`DeleteFunc` и ряд других функций обнуляют оставшийся хвост. Если реализуешь удаление сам, сохрани `oldLen` и обнули `clear(a[len(a):oldLen])`, предварительно расширив длину до `oldLen` при необходимости и убедившись, что нет других владельцев хвоста.

### 13. `slices.Grow` — гарантия ёмкости, но не сохранения адресов

```go
s := make([]int, 1, 1)
p := &s[0]
s = slices.Grow(s, 100)
s[0] = 9
fmt.Println(*p) // может остаться старое значение 0
```

Рост ёмкости может заменить backing array. **Почему:** pointer `p` остаётся указателем на элемент старого массива, не перенаправляется на новый. `slices.Grow` не меняет длину. Не передавай наружу `&s[i]`, если дальше собираешься расширять `s`.

### 14. `clear(s)` не меняет длину

```go
s := []int{1, 2, 3}
clear(s)
fmt.Println(s, len(s)) // [0 0 0] 3
```

`clear` для слайса обнуляет **текущие элементы**, а для map удаляет записи. Один и тот же встроенный идентификатор, разные контракты. `clear(s)` не освобождает backing array и не меняет `len/cap`.

### 15. `append` из строки

```go
b := []byte("Go")
b = append(b, "lang"...)
fmt.Println(string(b)) // Golang
```

Это специальная форма встроенного `append`: строка раскладывается на байты при `...`. Она не декодирует Unicode rune.

### 16. Пустой `range`, `nil` и JSON

```go
var a []int
b := []int{}
fmt.Println(a == nil, b == nil) // true false
fmt.Println(len(a), len(b))     // 0 0
out1, _ := json.Marshal(a)
out2, _ := json.Marshal(b)
fmt.Println(string(out1), string(out2)) // null []
```

**Причина:** nilness — часть значения слайса, а не только его длина. Для API, где поле должно сериализоваться как `[]`, возвращай непустой заголовок пустого слайса (`[]T{}`), а не `nil`.

### 17. `range` запоминает длину, но не копирует элементы слайса

```go
s := []int{1, 2, 3}
for i, v := range s {
    if i == 0 { s[1] = 99 }
    fmt.Print(v, " ")
}
// 1 99 3
```

Количество итераций определяется длиной при входе в цикл. Но значения элементов читаются по мере обхода **того же backing array**; это отличается от `range` по массиву. Если в цикле `s = append(s, ...)`, новые элементы не добавятся к числу итераций.
