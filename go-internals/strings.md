# Строки (`string`): байты, UTF-8, rune, память и конвертация

## 1. Модель

`string` — неизменяемая последовательность **байтов**, которая по соглашению обычно содержит UTF-8. Концептуально значение хранит указатель на байты и длину; конкретный layout — деталь ABI. Строка может содержать произвольные, в том числе некорректные UTF-8 байты.

**Каверза:** `len(string)` возвращает число **байтов**, не букв/символов/графем.

```go
s := "Привет"
fmt.Println(len(s))                 // 12
fmt.Println(utf8.RuneCountInString(s)) // 6
```

## 2. Индексация и `range`

`s[i]` возвращает байт `byte`; `range s` декодирует UTF-8 и выдаёт **индекс первого байта rune** и сам `rune` (Unicode code point).

```go
s := "AЖ"
for i, r := range s {
    fmt.Printf("%d %c\n", i, r)
}
// 0 A
// 1 Ж
```

Для некорректного UTF-8 `range` даёт `utf8.RuneError` и продвигается на 1 байт в соответствующем случае.

## 3. `rune` != визуальный символ

Unicode code point (rune) может быть одной из нескольких частей составной графемы. Комбинируемые символы и emoji-sequences могут состоять из нескольких rune, отображаясь как один видимый символ. Если задача именно «количество пользовательских символов», `utf8.RuneCountInString` недостаточно: нужна сегментация grapheme clusters.

## 4. Неизменяемость

`s[0] = 'X'` — ошибка компиляции. Чтобы менять байты, сконвертируй в `[]byte` и затем обратно:

```go
b := []byte(s)
b[0] = 'X'
newString := string(b)
```

Это меняет **байты**, не гарантируя корректность Unicode. Для изменения по rune нужна отдельная операция над `[]rune` или библиотека Unicode.

## 5. Строковый под-срез может удерживать память

`small := huge[:10]` обычно даёт подстроку, разделяющую исходный набор байтов; пока жив `small`, большая область может удерживаться. Если нужно отделить короткое значение, `strings.Clone(small)` делает независимую копию байтов (если это полезно в данном случае).

## 6. `[]byte(s)` и `string(b)`

Логически конверсия создаёт независимое значение с защитой неизменяемости строки. Компилятор может оптимизировать физические копии, когда может доказать безопасность; **не рассчитывай на конкретное количество аллокаций** без бенчмарка. В обычном безопасном коде изменение `b` после `string(b)` не должно изменить строку.

## 7. Сравнение и `map` ключ

Строки сравниваются лексикографически по байтам и могут быть ключами `map`. Две строки, визуально выглядящие одинаково, могут иметь разную нормализацию Unicode и разные последовательности байтов: `"é"` может быть одной rune или `e` плюс combining accent. Если бизнес-ключи требуют Unicode-equivalence, нормализуй явно.

## 8. Сборка строки

Многократное `s += piece` в большом цикле может приводить к повторным выделениям/копированию. `strings.Builder` или `bytes.Buffer` часто эффективнее, но нужно сравнивать на фактической нагрузке.

**Каверза:** нельзя копировать `strings.Builder` после начала использования; для `Builder.String()` применимы особенности внутреннего буфера, поэтому использовать builder только по документированному API, не пытаться мутировать его старую память через unsafe.

## Дополнительные Unicode- и memory-каверзы

### 10. Некорректный UTF-8 разрешён

```go
s := string([]byte{0xff, 'A'})
fmt.Println(len(s)) // 2
for _, r := range s {
    fmt.Printf("%U ", r) // U+FFFD U+0041
}
```

Строка — байты, не тип «валидная UTF-8 последовательность». `range` заменяет некорректный байт на rune `U+FFFD` при декодировании; исходный байт `0xff` при этом остаётся в строке. Для проверки использовать `utf8.ValidString(s)`.

### 11. `s[i:j]` режет байты и может разорвать символ

```go
s := "Ж"
fmt.Println(len(s)) // 2
part := s[:1]        // первый байт UTF-8
fmt.Println(utf8.ValidString(part)) // false
```

Срез строки не знает границы rune. Поэтому «взять первые 10 символов» нельзя реализовать как `s[:10]` без отдельной логики.

### 12. Нормализация: визуально идентичные строки могут отличаться

```go
a := "\u00e9"
b := "e\u0301"
fmt.Println(a == b) // false
```

Unicode допускает несколько кодовых последовательностей для визуально одинакового текста. Для сравнения/ключей, где важна каноническая эквивалентность, сначала нормализуй (например, `golang.org/x/text/unicode/norm`). Не выполняй «lowercase» на уровне ASCII, если работаешь с произвольным языком.

### 13. Почему `strings.Builder` помогает

`s += piece` в цикле может многократно копировать накопленные байты. `strings.Builder` аккумулирует данные в буфере и избегает лишних копий, если подходит по API. Не копировать использованный Builder — это требование документации; `Grow` увеличивает запас ёмкости, но не длину.

### 14. `strings.Clone` при маленькой подстроке

`short := huge[:10]` может удерживать огромную строку в памяти, поскольку указатель короткой строки ссылается на тот же байтовый блок. `short = strings.Clone(short)` отделяет необходимые байты. Это полезно при парсинге больших текстовых документов, когда нужны только короткие ключи.
