# `sync.Once`: инициализация один раз, panic, рекурсия, retry

## 1. Что гарантируется

`Once.Do(f)` запускает `f` не более одного раза для конкретного экземпляра `Once`. Последующие `Do` ждут завершения первого вызова и не запускают `f` заново. Публикация результатов `f` синхронизирована с возвратом других `Do`. Концептуально применяется флаг завершённой инициализации плюс синхронизация, но exact layout не является контрактом.

```go
var once sync.Once
var config *Config
func GetConfig() *Config {
    once.Do(func() {
        config = loadConfig()
    })
    return config
}
```

## 2. Почему простая проверка bool неверна

```go
if !initialized {
    initialized = true
    initData()
}
```

При двух горутинах это data race и потенциальная двойная инициализация, а установка флага до `initData` делает возможным наблюдение неполного состояния. Замена `bool` на atomic flag сама по себе недостаточна: второй worker может увидеть флаг `true`, пока первый **ещё выполняет** инициализацию. `Once` ждёт окончания.

## 3. Если `f` паникует

`Once` считает вызов `f` состоявшимся даже при panic. **Нового запуска не будет** — это важная ловушка при инициализации с ошибками. Не жди automatic retry после panic.

## 4. Если `f` возвращает ошибку

`Do` принимает только `func()`, поэтому захвати результат во внешнюю переменную:

```go
var once sync.Once
var value *Client
var initErr error
func ClientInstance() (*Client, error) {
    once.Do(func() { value, initErr = newClient() })
    return value, initErr
}
```

Все последующие вызовы увидят **ту же** ошибку. `sync.OnceValues` / `sync.OnceValue` удобно возвращают сохранённые результаты, но **не выполняют retry** при ошибке.

Если ошибка временная и требуется повтор, нужен иной протокол (mutex + state machine / singleflight + retry), а не `Once`.

## 5. Рекурсивный `Do`: deadlock

```go
var once sync.Once
once.Do(func() {
    once.Do(func() {}) // ждёт завершения самого себя
})
```

Внешний `Do` ещё не закончил `f`, внутренний `Do` ждёт его завершения. Не вызывай повторно тот же `Once` из собственного init path.

## 6. Копирование `Once`

Не копируй `Once` после первого использования. Структуры с `Once` обычно должны иметь pointer receivers. Переприсваивать использованный экземпляр `Once{}` для «сброса» без полной внешней координации нельзя.
