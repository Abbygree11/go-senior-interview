# `sync.Pool`: переиспользование объектов, GC, гонки владения

## 1. Что делает пул

`sync.Pool` временно хранит объекты, которые дорого создавать часто и которые могут безопасно использоваться повторно. `Put(x)` делает объект доступным для будущего `Get()`; `Get()` **не гарантирует** возврат ранее добавленного объекта — пул может быть очищен runtime.

```go
var bufPool = sync.Pool{
    New: func() any { return new(bytes.Buffer) },
}
func use() {
    b := bufPool.Get().(*bytes.Buffer)
    b.Reset()
    defer bufPool.Put(b)
    // работа с b
}
```

## 2. Почему `sync.Pool` — не обычный кэш

Runtime может удалить элемент из пула в любой момент без уведомления (часто это связано с GC). Поэтому **никогда не хранить** там единственную копию важных данных, сеансов или незавершённых задач. Если нужна гарантированная ёмкость/стабильное хранение — собственный bounded pool с lock/channel.

## 3. Владение после `Put`

```go
b := bufPool.Get().(*bytes.Buffer)
bufPool.Put(b)
b.WriteString("oops") // ПЛОХО: другой worker мог взять тот же b
```

После `Put` объект перестаёт быть эксклюзивно твоим. Одновременное использование может вызвать data race и порчу данных. `Get/Put` синхронизированы как операции пула, но **не делают сам объект безопасным для совместной мутации**.

## 4. Обнуление и безопасность данных

Повторно выданный объект может содержать старые значения. `bytes.Buffer.Reset` сбрасывает длину, но не обязательно затирает все байты внутри backing array. Если предыдущие данные чувствительны, просто `Reset` может быть недостаточен: оцени необходимость явной очистки и политику хранения/перевыделения.

## 5. Накладные расходы и ложная оптимизация

Объект, который не выделяется в heap, необязательно выгодно хранить в `sync.Pool`: интерфейсная упаковка, переинициализация, удержание больших буферов и GC могут сделать хуже. `sync.Pool` часто полезен для временных объектов, разделяемых многими независимыми клиентами, но **доказывать выгоду бенчмарком**.

## 6. `New` и nil

Если пул пуст и `New` не задан, `Get()` может вернуть nil. Если задан `New`, при пустом пуле вызывается функция создания; код всё равно должен учитывать контракт конкретного пула.

## 7. Копирование пула

`sync.Pool` нельзя копировать после начала использования. Лучше использовать один разделяемый экземпляр, обычно на уровне пакета/сервиса, если у всех потребителей одинаковый контракт сброса состояния.
