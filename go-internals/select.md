# `select`: готовность, `nil`-ветки, случайный выбор, отмена, starvation

## 1. Механика

`select` выбирает **одну готовую операцию** чтения/отправки на канале. Если одновременно готовы несколько операций, выбирает одну через равномерный псевдослучайный выбор. Если ни одна не готова, выполняет `default` (если есть) либо блокируется.

Это не порядок сверху вниз, не «первый case сработает первым» и не приоритет `ctx.Done()`.

```go
select {
case v := <-a:
    fmt.Println("a:", v)
case b <- 10:
    fmt.Println("sent to b")
default:
    fmt.Println("nothing ready")
}
```

## 2. Вычисление выражений при входе в `select`

Выражения каналов и правые части выражений отправки вычисляются **один раз, в исходном порядке** при входе в `select`, даже если их ветка не будет выбрана. Это может выполнять побочные эффекты.

```go
func side() int { fmt.Print("SIDE "); return 7 }
var ch chan int
select {
case ch <- side(): // side() вызывается, хотя ch == nil
default:
    fmt.Println("default")
}
// SIDE default
```

Но тело невыбранного `case` не выполняется. Это часто задают на собеседовании.

## 3. `nil`-канал отключает ветку

```go
var ch <-chan int // nil
select {
case v := <-ch:
    fmt.Println(v)  // никогда не выбирается
default:
    fmt.Println("no data") // no data
}
```

Ненулевой канал без данных и отправителей — **не то же**: он может стать готовым позже. Если все каналы `nil` и нет `default`, `select` блокируется навсегда.

## 4. Закрытый канал всегда готов к чтению

После исчерпания буфера чтение закрытого канала сразу возвращает `zero, false`. В цикле `select` такая ветка может срабатывать бесконечно:

```go
for {
    select {
    case _, ok := <-ch:
        if !ok {
            // continue — НЕ отключает ветку
            ch = nil // исключаем из будущих выборов
        }
    case <-done:
        return
    }
}
```

Если после `ch = nil` другие ветки никогда не готовы, горутина теперь будет ждать их, а не «сама завершится». Для единственного рабочего канала можно просто `return`.

## 5. `ctx.Done()` не приоритет

```go
select {
case out <- value:
case <-ctx.Done():
    return
}
```

Если контекст отменён, но `out` одновременно готов, отправка **всё ещё может произойти**. Для отказа от *намеренного начала* отправки часто делают предварительную проверку `ctx.Err()`, но между проверкой и `select` возможна отмена: строгой гарантии «ни одного send после cancel» не будет без дополнительной синхронизации.

## 6. `default` и busy loop

```go
for {
    select {
    case v := <-ch:
        process(v)
    default:
        // ничего — бесконечный активный цикл с CPU
    }
}
```

`default` — неблокирующий путь, а не «отложенное ожидание». Если нужна реакция на отмену или таймер, добавь реальные blocking cases. `time.Sleep` в бесконечном default — временный костыль; обычно лучше перестроить протокол.

## 7. Чтение из нескольких каналов: отключение завершённых

Для fan-in `select` с переменными каналов `a,b` нужно при `!ok` присваивать **именно эту локальную переменную** `nil`, иначе закрытый канал будет постоянно доступен. Когда все каналы стали nil, нужно явно закончить цикл — ожидание пустого `select` без `default` не завершается.

```go
for a != nil || b != nil {
    select {
    case v, ok := <-a:
        if !ok { a = nil; continue }
        use(v)
    case v, ok := <-b:
        if !ok { b = nil; continue }
        use(v)
    }
}
```

## 8. `select` и fairness

Псевдослучайный выбор готовой ветки не является гарантией «каждая получит сервис за N шагов». Если нужен **строгий приоритет** важной работы, его придётся моделировать (например, в два этапа), аккуратно учитывая гонки и отмену. Случайность помогает не зафиксировать один порядок, но не доказывает детерминированную fairness.

## 9. Канал для отправки в `select` тоже может запаниковать

```go
ch := make(chan int)
close(ch)
select {
case ch <- 1: // panic, если эта ветка выполняется
default:
}
```

Закрытая отправка не превращается в «неготовую» ветку, и `default` здесь не должен рассматриваться как безопасный fallback. Не используй закрытие data channel как способ заставить send-case молча проиграть.

## 10. `select{}`, empty select, блокировка

`select {}` без веток блокируется навсегда. Полезно знать как логический факт, но это не полезный shutdown-механизм.
