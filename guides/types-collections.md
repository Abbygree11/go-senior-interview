# Типы Go, коллекции и неожиданные эффекты

## 1. Slice header
**Устройство.** `[]T` концептуально содержит pointer + len + cap, указывает на базовый массив.
**Каверза.** Передача слайса в функцию копирует заголовок, не массив; запись элемента видна другим слайсам, а изменение локального `len` — нет.
**Защита.** Возвращать новый слайс после `append`, если надо обновить заголовок вызывающего кода.

## 2. `append` и общий массив
**Устройство.** Если хватает `cap`, `append` пишет в существующий массив; иначе выделяет новый.
**Каверза.** `s := a[:1]; s = append(s, 99)` может переписать `a[1]` «незаметно».
**Защита.** Ограничить ёмкость `s := a[:1:1]` или сделать `slices.Clone`, когда нужна независимость.

## 3. `nil` slice vs empty slice
**Устройство.** `var s []int` — nil-слайс, `[]int{}` — ненулевой пустой слайс; оба имеют len 0 и допускают append.
**Каверза.** `reflect.DeepEqual` различает их; `encoding/json` обычно выдаёт `null` для nil и `[]` для пустого.
**Защита.** Явно оговаривать контракт API и тестировать сериализацию.

## 4. Массив vs слайс
**Устройство.** `[N]T` — значение с N элементами; `[]T` — представление области массива.
**Каверза.** Передача массива по значению копирует элементы, передача слайса — нет.
**Защита.** Выбирать нужную семантику владения; не путать указатель на массив и slice.

## 5. `map`: nil, отсутствие ключа, итерация
**Устройство.** `nil` map можно читать, `len` равно 0, запись вызывает panic. `v := m[k]` возвращает zero value и при отсутствии ключа.
**Каверза.** Без `v, ok := m[k]` можно перепутать отсутствующий ключ с нулевым значением. Порядок range по map не определён.
**Защита.** `make(map[K]V)`; `comma, ok`; сортировка ключей, если нужен порядок.

## 6. `map` и конкурентность
**Устройство.** Встроенная map не защищена для конкурентного чтения + записи.
**Каверза.** Data race, возможная фатальная ошибка runtime; concurrent reads без writers допустимы.
**Защита.** Mutex/RWMutex или `sync.Map`. Не пытаться поймать runtime fatal error через `recover`.

## 7. Внутренности `map` зависят от Go
**Устройство.** Hash table, разрешение коллизий и стратегия роста — детали runtime, а не спецификация языка. В Go 1.24 встроенная реализация была переработана на основе Swiss Tables.
**Каверза.** Объяснения, построенные только на старых `bmap`, overflow buckets и «эвакуации бакетов», нельзя выдавать за универсальный контракт актуального Go.
**Защита.** На собеседовании отделять API-гарантии от реализации конкретной версии.

## 8. Interface и typed nil
**Устройство.** Интерфейс концептуально хранит динамический тип и значение; nil только если отсутствуют оба.
**Каверза.** `var p *MyError = nil; var err error = p` → `err != nil`; `error(p)` не исправляет.
**Защита.** Возвращать `nil` прямо, когда ошибки нет; не передавать typed nil как `error`.

## 9. Value receiver и pointer receiver
**Устройство.** Method sets у `T` и `*T` различаются; методы с pointer receiver доступны в method set `*T`.
**Каверза.** `T` может не реализовывать интерфейс, хотя вызов `value.Method()` компилируется благодаря адресуемости значения. Копирование структуры с mutex опасно.
**Защита.** Продумывать receiver и методы интерфейса; `go vet -copylocks`.

## 10. Строка и `range`
**Устройство.** Строка — неизменяемая последовательность байтов, обычно UTF-8 по соглашению, но может содержать произвольные байты; `range` декодирует Unicode code points.
**Каверза.** `len("привет")` возвращает число байтов, а не букв; индексирование `s[i]` выдаёт байт.
**Защита.** `utf8.RuneCountInString` для числа code points; grapheme clusters — отдельная задача, не равная количеству rune.

## 11. `defer`: аргументы и замыкания
**Устройство.** Аргументы отложенного вызова вычисляются немедленно при регистрации `defer`; само тело вызывается при выходе из окружающей функции, LIFO.
**Каверза.** `defer fmt.Println(x)` печатает старое значение, а замыкание с чтением `x` — значение в момент исполнения. Замыкание может изменить именованный результат после `return value`.
**Защита.** Явно передавать значения параметрами, когда нужен snapshot.

## 12. `defer` внутри цикла
**Устройство.** Граница выполнения `defer` — функция, а не блок `{}` и не итерация.
**Каверза.** `defer f.Close()` в цикле удерживает все открытые fd до выхода из функции.
**Защита.** Выносить тело одной итерации в функцию; если закрываете вручную — гарантировать cleanup на всех путях и учитывать ошибку `Close`.

## 13. `range` и версии Go
**Устройство.** Для переменных, объявленных `:=` в цикле, Go 1.22+ ввёл отдельные переменные каждой итерации при соответствующей версии модуля.
**Каверза.** Старая загадка «все замыкания видят последнюю переменную `range`» больше не универсальна; если переменная объявлена заранее и переиспользуется (`var v T; for _, v = range ...`), общая переменная остаётся.
**Защита.** Смотреть директиву `go` в `go.mod`; при необходимости передавать значения явными аргументами.

## 14. `nil` receiver
**Устройство.** Метод с pointer receiver можно вызвать на nil-указателе, если внутри метод не разыменовывает его без проверки.
**Каверза.** Вызов метода на nil не обязан сразу паниковать, но обращение к полям через nil обычно приведёт к panic.
**Защита.** Явно задавать контракт nil receiver; не использовать его как скрытое состояние без причины.

## 15. `==`, comparability и interface
**Устройство.** Slice, map, function сравнимы только с `nil`, кроме некоторых специальных случаев; динамический тип внутри interface тоже влияет на сравнение.
**Каверза.** Сравнение двух interface, содержащих несравнимые динамические значения (например, slice), может вызвать panic.
**Защита.** Для структурного сравнения использовать подходящую семантику (`slices.Equal`, `maps.Equal`, явно заданные правила).

## 16. `copy` и aliasing
**Устройство.** `copy(dst, src)` копирует минимум len элементов; перекрывающиеся участки поддерживаются.
**Каверза.** Копирование слайса заголовком не отделяет память, а `copy` отделяет только если dst имеет **собственный** базовый массив.
**Защита.** `dst := append([]T(nil), src...)` или `slices.Clone(src)` для независимого массива; осторожно с вложенными ссылочными полями.
